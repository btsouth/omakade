# Omakade 1.9 testing candidate

This local candidate combines three reviewed work streams:

- matching, artwork recovery, library-review, and launch correctness fixes;
- optional cached ProtonDB badges for Steam store games;
- versioned emulator save protection with journaled restore recovery.

It is a testing candidate, not publication approval. Xenia and the TV/Gamescope helper
remain outside this scope.

## Candidate identity

- Branch: `codex/1.9-testing`
- Version: `1.9.0`
- Base release: `v1.8.0` (`5ba99e6`)
- Final commit, executable hashes, staged paths, and check results are written to
  `build/1.9-testing/candidate.json` after the candidate is committed and rebuilt.

Do not test an older installed binary by accident. Close Omakade before starting the staged
binary so single-instance activation cannot forward to another version.

## Automated gate

Run from a clean candidate commit:

```bash
cmake --preset release
cmake --build --preset release
ctest --preset release --output-on-failure
python tests/SbomGeneratorTests.py
desktop-file-validate packaging/io.github.tsouth89.Omakade.desktop
appstreamcli validate packaging/io.github.tsouth89.Omakade.metainfo.xml
```

Install into an empty staging root, verify the installed executables, and run the staged
smoke test with isolated configuration and data. Build a local Arch package from a commit
archive, then test clean install, upgrade from 1.8.0, reinstall, removal, and reinstall in
a disposable environment. No workflow dispatch, push, tag, attestation, or publication is
part of the local gate.

## Safe local installation

Do not switch the app or recorder while any game or supported emulator is running.

1. Record the current app and recorder targets and hashes.
2. Back up the user desktop entry, recorder override, settings, and a consistent SQLite
   library snapshot into an owner-only rollback directory.
3. Install the staged tree under `~/.local/lib/omakade/<candidate-commit>/`.
4. Verify installed hashes against the staged manifest before changing links.
5. Point the user commands, desktop entry, and recorder override at the candidate.
6. Reload user systemd and restart the recorder only between game sessions.
7. Run an isolated smoke test before opening the normal library.

Binary rollback restores the saved links, desktop entry, and recorder override. Keep newer
library history and save snapshots unless data recovery is specifically required.

## End-to-end acceptance

### Maintenance and launching

1. Refresh the normal library and inspect Needs Review, missing-artwork, Favorites, Recent,
   and multi-source empty states.
2. Correct one ambiguous game match and one artwork choice; restart and confirm both persist.
3. Launch normal SNES, N64, Dreamcast, and Cemu WUA entries. Confirm the selected runtime,
   controller input, return to Omakade, and recorded playtime.
4. Verify an archived RetroArch entry remains with RetroArch and reports a missing container
   clearly without changing its selected core.

### ProtonDB

1. Confirm badges are absent until enabled in Settings.
2. Enable badges and inspect known Steam store games on desktop cards, Couch Mode, and details.
3. Check report count, cache date, and provider link. Verify non-Steam shortcuts, manual games,
   and emulator entries remain neutral.
4. Restart offline and confirm cached results remain. Disable badges and confirm they disappear.
5. For a linked Steam/manual game, switch installations and confirm only the Steam store
   installation receives a rating.

### Save protection

1. Launch a supported game with existing progress and confirm a verified snapshot appears
   before the emulator starts. Confirm an unchanged save does not create a duplicate.
2. Exercise Save Backups with a physical controller. Cancel must receive initial focus, and
   shared-storage warnings must be explicit.
3. Test restore and interrupted-restore recovery only with disposable saves or a deliberately
   prepared copy. Never use an irreplaceable live save for routine acceptance.
4. Verify current progress is protected before restore, deleted members are handled, external
   changes are not overwritten, and unresolved recovery blocks emulator launch.
5. Check one native layout, one Flatpak layout when available, and the configured portable
   Bloodborne/Eden layouts without changing their launch commands.

### Lifecycle

1. Restart Omakade and the recorder between game sessions; confirm settings, cached ProtonDB
   data, save history, and personal library choices persist.
2. Disable networking and repeat core browsing and launching.
3. Confirm close-after-launch, launcher return, session attribution, and an ordinary shutdown.
4. Record architecture, package path, commit, and any unavailable hardware or Flatpak coverage.

## Known limits

- ProtonDB is best effort and has no stable versioned provider contract.
- Save-layout adapters do not prove every emulator version, wrapper, or filesystem provider.
- Process-argument recording cannot observe games loaded only through an emulator file picker.
- ARM64 CI is not physical ARM64 acceptance.
- OPR delivery is controlled by the Omarchy package repository and remains separate.

Before any push or publication, report the exact candidate commit, checks, limitations, and
manual results, then obtain explicit maintainer approval.
