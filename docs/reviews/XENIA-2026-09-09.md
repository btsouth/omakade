# Local Xenia review

Reviewed PR #44 at `5cd2a395da38d091852808b617b1cf86c2203615` against its base
`b1c8311177eb8809ef4f382aa0054d14aa95c1e4`. No review was posted and no code was merged.

Recommendation: defer integration pending corrections and real launcher acceptance.

- Both architecture CI jobs fail `xeniaLauncherBuildsSafeCommands`: the command
  has no arguments when the test expects a game path. `xeniaCommand` resolves an
  installed executable before returning a command, but this test supplies none.
  Make the command test deterministic using a temporary executable on a private
  PATH; retain a separate missing-emulator test.
- `XeniaScanner.cpp::discExtensions` accepts `.zar`, while
  `GameLauncher.cpp::validXeniaPath` only accepts `.iso` and `.xex`. Imported `.zar`
  entries cannot launch. Align the supported formats with the actual runtime.
- `normalizeWindowsPath` removes every drive letter. Only a verified Wine Z:
  root mapping can justify that conversion. C: and custom drives need their
  prefix's drive mappings or an explicit unsupported-path result.
- `recentTitles` recognizes only single-quoted strings and assumes `path` appears
  before `title_name`. Valid alternate TOML string syntax and key order are lost.
  Use the actual writer's versioned fixtures and a proper parser or narrowly
  documented parser with coverage for both string forms and field order.
- `XeniaScanResult::incomplete` is never set by the scanner. Missing recent game
  files are skipped, and the model marks unseen rows inactive after the scan.
  An unavailable game drive can therefore hide cached games. Preserve cached
  availability/state on inaccessible roots and incomplete reads.
- The model reports zero hours and last played, and does not use the current
  session-recording integration. Integrate the current source contract before
  presenting Xenia as equivalent to the existing emulator sources.
- The implementation is based on an older main. Current navigation, console
  sources, backups, saved filters and discovery require a fresh integration review.

These findings come from source inspection and the existing CI logs. No emulator
launch or gameplay test was performed. The existing review
worktree was left unchanged. A successful native executable or user wrapper,
launch/exit/return, disconnected storage, personal-state round trip and controller
acceptance remain needed before integration.
